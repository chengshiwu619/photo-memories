### 1.2 `services/pipeline.py` ClassifyStage 交互逻辑失效（严重）

当前 Pipeline 的分类流程有时序错误：

```python
# services/pipeline.py Pipeline.run()
if isinstance(stage, ClassifyStage):
    self._classify_event.clear()
    result = stage.run(progress_callback=self._on_progress)   # ① 先跑 stage.run()
    needs_user = result.get("needs_user", [])
    if needs_user:
        self.interactive_classify_needed.emit(needs_user)     # ② 才让用户选
        self._classify_event.wait()
        self._classify_event.clear()
        stage.set_interactive_results(self._pending_classify_results)  # ③ 把结果传回
        # 但 stage.run() 已经返回了，传回来也没用！
```

再看 `ClassifyStage.run()`：

```python
def run(self, progress_callback=None) -> dict:
    result = classify_folders(progress_callback=progress_callback)
    needs_user = result.get("needs_user", [])
    for branch_path, category in self._interactive_results:   # ← 永远是空 list
        propagate_branch_category(branch_path, category)
    return {"classified": result.get("classified", 0), "needs_user": needs_user}
```

结果：用户在对话框里选的分类永远不会被传播到子文件夹。这是重构引入的新 bug（旧 StartupWorker 里是 wait 完再 propagate 的）。

建议修复：把 ClassifyStage 拆成两阶段，或者把 propagate 逻辑搬到 Pipeline 里：

```python
class ClassifyStage(Stage):
    name = "分类文件夹"

    def run(self, progress_callback=None) -> dict:
        from classifier.folder_classifier import classify_folders
        return classify_folders(progress_callback=progress_callback)

    def apply_user_results(self, results: list):
        """在用户完成交互后调用"""
        from classifier.folder_classifier import propagate_branch_category
        for branch_path, category in results:
            propagate_branch_category(branch_path, category)

# Pipeline.run() 改为
if isinstance(stage, ClassifyStage):
    result = stage.run(progress_callback=self._on_progress)
    needs_user = result.get("needs_user", [])
    if needs_user:
        self.interactive_classify_needed.emit(needs_user)
        self._classify_event.wait()
        self._classify_event.clear()
        stage.apply_user_results(self._pending_classify_results)  # ← 事后传播
```

### 1.3 `img.draft()` 导致原图尺寸被污染

`indexer/photo_indexer.py`：

```python
with Image.open(filepath) as img:
    img.draft("RGB", THUMBNAIL_SIZE)   # ← draft 之后 img.size 已经被缩小
    img = _auto_rotate(img)
    w, h = img.size                    # ❌ 这里拿到的是 draft 之后的尺寸
    img.thumbnail(THUMBNAIL_SIZE, Image.LANCZOS)
```

`draft()` 会让 JPEG 解码器按 1/2、1/4、1/8 预降采样，此时 `img.size` 已不是原始尺寸。这导致 `photo_metadata.width / height` 存的是降采样后的尺寸（可能是 200×150 而不是 4000×3000）。

修复：

```python
with Image.open(filepath) as img:
    orig_w, orig_h = img.size       # ← 先读原始尺寸（header only, 不解码）
    img.draft("RGB", THUMBNAIL_SIZE)
    img = _auto_rotate(img)
    img.thumbnail(THUMBNAIL_SIZE, Image.LANCZOS)
    if img.mode in ("RGBA", "P"):
        img = img.convert("RGB")
    img.save(thumb_path, "JPEG", quality=80)
return thumb_path, orig_w, orig_h
```

注意：旋转前读的 orig_w/h 对竖拍照片可能需要 swap，但原来的代码也是这样处理的，保持一致即可。

## 🟡 二、重要问题（架构或性能）

### 2.1 虚拟瀑布流目前会"一次性加载全部缩略图"

`ui/components/virtual_waterfall.py` 的 `_compute_layout`：

```python
def _compute_layout(self):
    for photo in self._photos:
        thumb = photo.get("thumbnail_path", "")
        height = self._card_width
        if thumb:
            pixmap = QPixmap(thumb)         # ❌ 每张都 load pixmap
            if not pixmap.isNull():
                pw, ph = pixmap.width(), pixmap.height()
```

6 万张图每次 `set_photos` 就要 QPixmap 加载 6 万次 —— 完全违背虚拟滚动的本意（原本就是为了避免这个）。

修复思路：
1. `photo_metadata` 表里已经存了 `width` 和 `height`，`load_category_photos_batch()` 多查这两列返回给 UI。
2. `_compute_layout` 只用 dict 里的 width/height 计算布局，不触碰文件。
3. `VirtualPhotoCard` 只在真正渲染进视口时才调用 `QPixmap(thumb)`，并用 `QPixmapCache` 做二级缓存。

```python
# ui/components/virtual_waterfall.py
def _compute_layout(self):
    for photo in self._photos:
        pw = photo.get("width") or 1
        ph = photo.get("height") or 1
        height = max(60, min(int(self._card_width * ph / pw), 800)) + GAP
        ...
```

另外 `resizeEvent` 会触发全量重算，6 万条就再来一轮。要加 debounce：

```python
def __init__(self, ...):
    self._resize_timer = QTimer(self)
    self._resize_timer.setSingleShot(True)
    self._resize_timer.setInterval(150)
    self._resize_timer.timeout.connect(self._do_relayout)

def resizeEvent(self, event):
    super().resizeEvent(event)
    self._resize_timer.start()
```

### 2.4 `LLMClient` 单例无法感知配置变更

```python
class LLMClient:
    _instance = None
    def __init__(self):
        from config import get_openai_client
        self._client = get_openai_client()   # ← 只在首次创建时读
```

当 `save_config()` 修改了 API Key 后：
- `config._OPENAI_CLIENT = None` ✓（会重建 OpenAI 底层 client）
- 但 `LLMClient._instance._client` 仍指向老的 OpenAI client

意味着用户改 API Key 后必须重启应用才能生效。修复：

```python
class LLMClient:
    _instance = None

    @classmethod
    def get_instance(cls):
        if cls._instance is None:
            cls._instance = cls()
        return cls._instance

    @classmethod
    def reset(cls):
        cls._instance = None

# config.save_config() 末尾加一行
from infra.llm.client import LLMClient
LLMClient.reset()
```
