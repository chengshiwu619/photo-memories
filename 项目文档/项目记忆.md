# 项目记忆

## 长期决策

- 项目是本地照片回忆库，不是云相册。
- 用户照片、缩略图、缓存、数据库都视为敏感数据。
- 所有照片默认都有回忆价值。
- AI 识图只做标签与分组，不做筛选与排除。
- 成人、写真、截图、生活照不默认排除。
- 重复、损坏才是状态问题。
- 特殊回忆是类似苹果相册 Memories 的故事卡片，不是简单 tag group。

## 当前产品边界

- 先做缩略图内容识别与视觉标签生产。
- path 标签是第一版稳定标签来源。
- SigLIP 是增强来源，不阻塞基础流程。
- 当前不做特殊回忆自动聚合大改。
- 当前不做 UI 大改。
- 当前不改 schema。
- 当前不全量跑 SigLIP。
- 当前不做人脸 / YOLO 批量推进。

## 关键踩坑

- `file_id` 不是稳定外部标识。
  DB 重建或重扫后，`memories`、`photo_tags`、`events` 等表可能出现悬空引用。
- `memories` 可以删后重建。
  它属于可再生数据，比强行保留旧引用更安全。
- 缩略图失败用 `thumbnail_path='__FAILED__'` 表示。
  查询、维护和识别链路都要显式处理这个状态。
- SQLite 写入要集中串行处理。
  并发 worker 只做图像处理，不直接写库。
- 真实 NAS / SMB 压力要保守控制。
  默认 workers 低，优先小批量。

## 标签治理规则

- path 标签是粗粒度来源标签，不是最终语义体系。
- path 标签要过滤容量词、数量残片、通用目录词。
- 历史 path 脏标签只清理 `source='path'`，不误删 `siglip`。
- 对 `dcim / mobile / sm-n9600 / moments` 这类词，先审计再决定删、改名还是保留。
- 后续标签治理优先走：
  1. 统计
  2. 审计
  3. 形成清洗计划
  4. 再执行

## AI 协作规则

- 先读现状，再改代码。
- 优先小步、低风险、可回滚。
- 不为了局部问题扩散到全链路重构。
- 不确定时先保留现有约定。
- 不把 mock 通过当成真实链路通过。
- 涉及真实库、真实缓存时，先 dry-run，再小批量 apply。

## 长任务规则

- 缩略图维护：先单文件，再 `limit=5`，再扩大。
- AI 标签：先 `path`，再小批量 SigLIP。
- 后台索引：保守并发，必要时回退 `workers=1`。
