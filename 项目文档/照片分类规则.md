# 照片二分类规则

本项目最终只输出两个业务分类：

- `1` 生活照片
- `2` 拍摄样片

统一规则入口在 `business/classifier/category_rules.py`。新增强规则、路径规则、最终 SQL 口径时应优先改这里，再由后台分类、随机瀑布流、时间线、回忆发现等入口复用。

## 分类来源

分类信息可能来自这些位置：

- `photo_metadata.category`：单张照片手动覆盖。
- `folder_categories.category`：文件夹分类结果，来自关键词、LLM、人工确认或精分修正。
- `sample_keywords` / `life_keywords`：用户自定义关键词。
- 强源目录规则：固定业务判断，不依赖用户关键词。

## 最终优先级

从高到低：

1. 强生活源目录：整棵目录树归生活。
1. 强样片文件名：单张照片归样片，可打穿强生活源目录。
2. 强生活源目录：整棵目录树默认归生活。
3. 强样片源目录：整棵目录树归样片。
4. 单张照片覆盖：`photo_metadata.category`。
5. 文件夹分类：`folder_categories.category`。
6. 用户样片关键词：命中文件名、文件夹名或路径时归样片。
7. 默认兜底：生活。

当前强生活源目录：

- `MobileBackup`
- `Mobile Backup`
- `Moments`
- `胶片成图`，但 `样片搜集` 子树除外

当前强样片源目录：

- `电报色图`
- `NSFW`
- `NSWF`
- 路径组件正好为 `NW`

当前强样片文件名：

- `JP-...-...-...-...`，例如 `JP-Mio-Ishikawa-石川澪-幻惑LIPS-0043-0748480480.jpg`
- `Photobook-YYYY-MM-DD-...`，例如 `Photobook-2021-12-27-Kana-Momonogi-桃乃木かな-Escape-0083-7883659235.jpg`

强样片文件名优先级高于强生活源目录；强生活源目录优先级高于强样片源目录。例如 `MobileBackup/.../JP-...jpg` 归样片，`Moments/NSFW/.../IMG_....jpg` 仍归生活。

## 后台文件夹分类

`business/classifier/folder_classifier.py` 负责把分类写入 `folder_categories`：

- `classify_folders()` 先处理强规则和关键词，再把不确定分支交给 LLM。
- `refine_sample_keywords()` 会对已存在结果做二次精分。
- 路径关键词按“越靠近照片文件夹越具体”比较优先级。
- 普通手动分类默认不被覆盖；但强源目录规则可以纠正强业务误判。

示例：

- `胶片成图/...` 默认归生活，即使有历史单张样片误标也按生活展示。
- `胶片成图/.../样片搜集/...` 是例外子树，可以继续归样片。
- `MobileBackup/.../样片搜集/...` 默认仍归生活。
- `MobileBackup/.../JP-Mio-Ishikawa-石川澪-幻惑LIPS-0043-0748480480.jpg` 这种强样片文件名按单张样片展示。
- `MobileBackup/.../Photobook-2020-12-10-Karen-Kawai-&-Tomoka-Kabasawa-SequenceNumber002-A-00005-0706709245.jpg` 和 `MobileBackup/.../Photobook-2021-12-27-Kana-Momonogi-桃乃木かな-Escape-0083-7883659235.jpg` 这种出版导出文件名也按单张样片展示。
- `电报色图/...`、`NW/...`、`NSFW/...` 归样片。

## 最终展示口径

随机瀑布流、时间线、收藏计数等入口应使用 `category_match_sql()` 或兼容包装 `_category_match_sql()`。

这层是最终兜底：即使数据库旧分类还没刷新，也应按统一规则展示。

## 回忆发现口径

回忆发现只应使用最终生活口径，不直接裸读 `fc.category = 1`。需要过滤生活照片时，使用 `category_match_sql(CATEGORY_LIFE)` 或已经按该规则计算过的 repository 返回值。

## 修改约束

- 不新增 schema 时，优先改 `category_rules.py`。
- 不把 AI 标签当作排除系统；AI 标签只辅助分组和故事。
- 生活照、成人、写真、截图不默认排除，只有强源目录或明确关键词决定二分类。
- 新增规则必须补测试，至少覆盖后台分类和最终展示 SQL。
