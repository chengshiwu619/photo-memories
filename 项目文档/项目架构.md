# 项目架构

## 1. 模块结构

- `ui/`
  负责页面、导航、瀑布流、时间线、特殊回忆卡片和图片查看。
- `services/`
  负责后台任务调度与生命周期。
- `business/`
  负责扫描、分类、索引、标签、回忆发现等业务流程。
- `infra/`
  负责数据库仓储、图像基础设施、LLM/模型调用封装。
- `core/`
  负责配置、模型、日志、checkpoint、数据库初始化。

## 2. 主数据流

### 2.1 扫描与索引

1. 扫描照片目录
2. 写入 `files`
3. 提取 EXIF / phash / 缩略图
4. 写入 `photo_metadata`
5. 标记重复图

### 2.2 标签

1. path 标签从目录结构提取
2. 可选 SigLIP 标签从缩略图推理
3. 统一写入 `photo_tags(file_id, tag, source)`

### 2.3 回忆

1. 从日期、目录、人物、标签等来源发现候选
2. 生成 `memories`
3. UI 以卡片堆叠方式展示

## 3. 数据库表用途

- `files`
  文件主表，记录 `file_path`、来源目录、是否图片。
- `photo_metadata`
  缩略图路径、日期、phash、重复图标记。
- `photo_tags`
  标签表，来源目前至少有 `path`、`siglip`。
- `memories`
  回忆卡片数据。
- `click_history`
  浏览点击记录。
- `photo_shown_history`
  已展示历史。
- `folder_categories`
  目录分类结果。
- `face_embeddings` / `face_clusters`
  人脸链路数据，当前不是重点。
- `events`
  事件/旅程聚合结果。
- `task_checkpoints`
  长任务断点续跑。

## 4. 缩略图主链路

- 统一写到缓存目录 `thumbnails/`
- 索引阶段生成
- UI、SigLIP、维护工具都读取同一套缩略图
- 失败缩略图用 `__FAILED__` 标记

## 5. 索引主链路

- `business/indexer/photo_indexer.py`
- 当前支持保守并发：
  - worker 负责读图、解码、缩略图生成、元数据提取
  - SQLite 写入仍串行
  - checkpoint 仍串行

## 6. 标签主链路

- `scripts/run_ai_labeling.py`
  默认跑 `source=path`
- `scripts/audit_path_tags.py`
  只读审计 path 标签
- `scripts/run_ai_recognition.py`
  SigLIP 小批量验证入口，属于增强链路

## 7. 回忆主链路

- `business/memory/memory_discovery.py`
  负责发现候选回忆
- `business/memory/memory_reasoning.py`
  负责反馈与负面提示

当前特殊回忆仍以既有规则和卡片生成逻辑为主，不等于“按标签自动聚类成故事”。

## 8. 主要脚本

- `scripts/check_integrity.py`
  完整性 dry-run 检查
- `scripts/maintain_thumbnails.py`
  缩略图失败重试与签名维护
- `scripts/run_ai_labeling.py`
  基础标签生产
- `scripts/audit_path_tags.py`
  标签审计导出

## 9. 当前架构边界

- 先保证缩略图、索引、基础标签稳定。
- 当前不做 UI 大改。
- 当前不改 schema。
- 当前不做全量 SigLIP。
- 当前不做人脸/YOLO 批量推进。
